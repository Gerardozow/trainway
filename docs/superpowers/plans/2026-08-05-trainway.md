# Trainway — Plan de implementación

> **Para trabajadores agénticos:** SUB-SKILL REQUERIDA: usar `superpowers:subagent-driven-development` (recomendado) o `superpowers:executing-plans` para implementar este plan tarea por tarea. Los pasos usan checkbox (`- [ ]`) para seguimiento.

**Objetivo:** Construir el MVP de Trainway — app web de entrenamiento de gimnasio que genera bloques de 4 semanas con IA, registra series offline desde el celular, y progresa automáticamente.

**Arquitectura:** SPA de React servida por un Cloudflare Worker en `gzow.dev/trainway`. El navegador habla directo con Supabase (Postgres + auth + RLS); el Worker existe solo para las llamadas a MiniMax, cuya key nunca toca el cliente. El catálogo de ejercicios va empaquetado en el repo, así que la app funciona sin conexión.

**Stack:** Vite 7 · React 19 · TypeScript 5.9 · Tailwind CSS v4 · React Router 7 · TanStack Query 5 · Dexie 4 · Supabase JS 2 · Cloudflare Workers (wrangler 4) · `@anthropic-ai/sdk` contra MiniMax · Recharts 3 · Vitest 3 · Playwright.

Spec de referencia: [2026-08-05-trainway-design.md](../specs/2026-08-05-trainway-design.md)

## Restricciones globales

- Node 24, npm 12. TypeScript en modo `strict`.
- Ruta base **`/trainway`** en todos lados: `base: '/trainway/'` en Vite, `basename="/trainway"` en el router.
- Interfaz **en español**. Ningún texto visible en inglés salvo nombres de ejercicio sin traducir aún.
- Acento único `#FFC603`. Gris de marca `#787878`.
  **Nunca** usar `#FFC603` como color de texto sobre fondo claro (~1.6:1, falla AA). Sobre fondo oscuro sí (~13:1).
- Objetivos táctiles mínimos de **48 px**. Móvil primero. Cero scroll horizontal.
- Secretos (`MINIMAX_API_KEY`, `SUPABASE_SERVICE_ROLE_KEY`) solo como secrets del Worker. Nunca con prefijo `VITE_`, nunca en el bundle del cliente.
- Todo `exercise_id` que se persista debe existir en `data/exercises.json`. Sin excepciones.
- Todas las tablas de usuario con RLS activo.
- Modelo de IA: `MiniMax-M3` vía `https://api.minimax.io/anthropic`.
- Commits en español, formato convencional (`feat:`, `fix:`, `test:`, `chore:`, `docs:`).

```js
const res = await fetch(URL)
if (!res.ok) throw new Error(`Descarga fallida: ${res.status}`)

  throw new Error(`Catálogo sospechoso: ${data.length} ejercicios`)

}

console.log(`OK: ${data.length} ejercicios guardados`)
```

```ts
type ProgressionScheme =
  | { type: 'double'; incrementKg: number }
  | { type: 'linear'; incrementKg: number }
  | { type: 'time'; incrementSeconds: number; maxSeconds: number }
  | { type: 'intensity' }

type SetResult = { reps: number | null; weight: number | null; durationSeconds: number | null; done: boolean }

type LastPerformance = { sets: SetResult[]; failedFloorStreak: number }

type Target = { sets: number; repRange: [number, number] | null; weight: number | null
              ; durationSeconds: number | null; note: string | null }

nextTarget(current: Target, scheme: ProgressionScheme, last: LastPerformance | null): Target
deloadTarget(t: Target): Target        // volumen 60%, intensidad 90%
parseRepRange(s: string): [number, number]
```

- [ ] **Paso 1: Escribir los tests que fallan**

`tests/progression.test.ts`:

```ts
import { describe, it, expect } from 'vitest'
import { nextTarget, deloadTarget, parseRepRange } from '@/lib/progression'

const scheme = { type: 'double', incrementKg: 2.5 } as const
const base = { sets: 4, repRange: [8, 10] as [number, number], weight: 60, durationSeconds: null, note: null }
const perf = (reps: number[], weight = 60) => ({
  sets: reps.map((r) => ({ reps: r, weight, durationSeconds: null, done: true })),
  failedFloorStreak: 0,
})

describe('parseRepRange', () => {
  it('interpreta un rango', () => expect(parseRepRange('8-10')).toEqual([8, 10]))
  it('interpreta un valor fijo', () => expect(parseRepRange('12')).toEqual([12, 12]))
})

describe('doble progresión', () => {
  it('sin historial deja el objetivo igual y marca calibración', () => {
    const out = nextTarget(base, scheme, null)
    expect(out.weight).toBeNull()
    expect(out.note).toMatch(/calibra/i)
  })

  it('con todas las series al tope del rango sube peso y vuelve al piso', () => {
    const out = nextTarget(base, scheme, perf([10, 10, 10, 10]))
    expect(out.weight).toBe(62.5)
    expect(out.repRange).toEqual([8, 10])
  })

  it('sin llegar al tope mantiene el peso', () => {
    const out = nextTarget(base, scheme, perf([10, 10, 9, 8]))
    expect(out.weight).toBe(60)
  })

  it('fallar el piso una vez mantiene el peso', () => {
    const out = nextTarget(base, scheme, { ...perf([8, 7, 6, 6]), failedFloorStreak: 1 })
    expect(out.weight).toBe(60)
  })

  it('fallar el piso dos veces seguidas aplica deload del 10%', () => {
    const out = nextTarget(base, scheme, { ...perf([7, 6, 6, 5]), failedFloorStreak: 2 })
    expect(out.weight).toBe(54)
  })

  it('las series sin marcar no cuentan como completadas', () => {
    const last = {
      sets: [
        { reps: 10, weight: 60, durationSeconds: null, done: true },
        { reps: 10, weight: 60, durationSeconds: null, done: true },
        { reps: 10, weight: 60, durationSeconds: null, done: true },
        { reps: 10, weight: 60, durationSeconds: null, done: false },
      ],
      failedFloorStreak: 0,
    }
    expect(nextTarget(base, scheme, last).weight).toBe(60)
  })

  it('redondea a múltiplos de 0.5 kg', () => {
    const out = nextTarget({ ...base, weight: 61.3 }, scheme, perf([10, 10, 10, 10], 61.3))
    expect(out.weight! % 0.5).toBe(0)
```

## Autorrevisión del plan

**Cobertura del spec.** Las 18 secciones del spec están cubiertas: arquitectura y stack (Tareas 1, 7), modelo de datos y RLS (5), catálogo (3), traducciones (8), integración con MiniMax (7, 8), progresión (4, 12), offline (10), UI y accesibilidad (2, 11, 13, 14, 15), despliegue (16), seguridad (5, 7, 8), pruebas (todas más 17), riesgos (mitigaciones repartidas: validación de IA en 7, idempotencia en 10, icono cuadrado en 15).

**Sin huecos detectados.** Las tres cosas que el spec dejaba abiertas están asignadas: los colores exactos ya se extrajeron y están en las restricciones globales; el icono cuadrado es la Tarea 15 Paso 1; las skills de diseño se leen desde la caché de plugins en la Tarea 2 Paso 1 y la Tarea 13 Paso 1.

**Consistencia de tipos.** `Target`, `ProgressionScheme`, `SetResult` y `LastPerformance` se definen en la Tarea 4 y se consumen con los mismos nombres en las Tareas 8, 11 y 12. `filterCandidates` y `getExercise` se definen en la Tarea 3 y se consumen igual en las Tareas 7, 8 y 11. `enqueueSet`, `flushQueue` y `pendingCount` se definen en la Tarea 10 y se consumen en las Tareas 11 y 14. `client_id` en la base es `clientId` en TypeScript; la conversión ocurre solo en `flushQueue`.
